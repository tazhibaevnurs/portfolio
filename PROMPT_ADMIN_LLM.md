# Промпт для реализации: HTML-админка портфолио + LLM + CV

Используй этот документ как **единую спецификацию** для разработки (или как системный промпт для LLM-агента). Стек: **Django** (проект `portfolio_django`), публичная главная страница портфолио, отдельная **кастомная админка на HTML** (не `django.contrib.admin`).

---

## Цель

Сделать веб-интерфейс администратора на обычных Django-шаблонах/HTML, где можно:

1. **CRUD проектов** — создавать, редактировать, удалять записи проектов.
2. **Видимость на сайте** — у каждого проекта флаг «показывать на главной / скрыть»; на публичной главной отображаются только видимые.
3. **Обогащение через LLM по Git-репозиторию** — при создании/редактировании пользователь вводит **краткое описание** и **URL Git-репозитория**; бэкенд **загружает содержимое репозитория** (README, структура, ключевые файлы в разумных лимитах), передаёт в **бесплатный LLM из интернета**, модель **заполняет остальные поля** красивым текстом для блока проекта на главной (название для карточки, краткий лейаут, технологии, выделенные фичи и т.д. — по текущей модели в `main.models`).
4. **Генерация CV** — в админке кнопка/раздел «Сгенерировать CV»: на основе **уже сохранённых проектов в БД** (желательно только видимых или с выбором) формируется **структурированное резюме** (текст/HTML/PDF по возможности), пригодное для скачивания или отображения.

---

## Ограничения и требования к UI

- Админка — **отдельные маршруты** и шаблоны, например `/manage/...` или `/portfolio-admin/...`, со списком, формой создания/редактирования, подтверждением удаления.
- **Не использовать** стандартный Django Admin для этих сценариев (можно оставить `admin.py` пустым или только для суперюзера технических моделей — по желанию, но пользовательский сценарий — только кастомные страницы).
- Защита: **логин** (`LoginRequiredMixin` / `@login_required`) или отдельная простая авторизация; CSRF на POST; не выкладывать секреты в шаблоны.

---

## Интеграция с Git

- Поддержать **публичные** репозитории (GitHub/GitLab/Gitee и т.д.): клонирование во временную директорию **или** REST API **raw/README** с лимитом размера и таймаутом.
- **Не** тащить в LLM весь репозиторий целиком: отобрать README, `package.json` / `requirements.txt` / `pyproject.toml`, несколько уровней дерева каталогов, при необходимости первые N строк ключевых файлов.
- Обработка ошибок: приватный репо, 404, таймаут — показать пользователю понятное сообщение, поля можно заполнить вручную.

---

## Интеграция с бесплатным LLM из интернета

- Использовать **один** из вариантов с **HTTP API** и **бесплатным или freemium** доступом (ключ или анонимно — по документации провайдера), например:
  - **Google Gemini API** (free tier),
  - **Groq** (быстрые модели, бесплатный лимит),
  - **Hugging Face Inference API** (ограничения по модели),
  - **OpenRouter** / другие агрегаторы с бесплатными моделями.
- Ключ хранить в **переменных окружения** (`.env`), не коммитить.
- Промпт к модели: строго **JSON или схема полей**, совпадающая с полями модели Django, чтобы парсить ответ без «ломания» шаблонов.
- Лимиты: обрезка контекста, одна попытка retry при невалидном JSON.

---

## Генерация CV

- Входные данные: список проектов из БД (название, описание, стек, даты, ссылки — что есть в модели).
- Выход: единый документ **«CV / портфолио резюме»** на русском или двуязычно — зафиксировать в настройках; формат минимум **HTML для печати** или **Markdown**, опционально PDF через библиотеку или «print to PDF».
- В админке: превью + кнопка «Скачать» / «Обновить текст CV».

## Технические задачи для разработчика/агента

1. Расширить или уточнить `Project` (или аналог) в `main.models`: флаг `is_visible`, поля под карточку главной, URL репозитория, сырые/обогащённые данные при необходимости.
2. Views + forms (или DRF — но для HTML-админки достаточно Django Forms) для CRUD.
3. Сервис: `repo_fetch` + `llm` + `enrichment` — собрать пайплайн «URL репо + описание пользователя → JSON полей → сохранение».
4. Отдельный endpoint/task «Generate CV» с вызовом LLM или шаблонной сборкой + опционально LLM для стилизации.
5. Тесты на парсинг ответа LLM и на видимость проектов на главной.

---

## Критерии готовности

- В кастомной HTML-админке можно создать проект, указать репозиторий и описание, нажать «Обогатить» (или авто при сохранении), увидеть заполненные поля и переключатель «на сайте».
- Главная показывает только отмеченные проекты.
- CV строится из текущих данных проектов и доступен из админки.

## Краткая версия (одним сообщением для LLM-агента)

> Реализуй в Django-проекте `portfolio_django` кастомную админку на HTML (не Django Admin): CRUD проектов с флагом отображения на главной. При сохранении: пользователь вводит описание и URL Git; бэкенд скачивает обзор репозитория (README + метаданные, с лимитами), вызывает бесплатный LLM через интернет (ключ из env), получает структурированные поля для карточки на главной. Добавь генерацию CV в конце админ-потока на основе проектов в БД. Защити маршруты лogin_required и CSRF.
