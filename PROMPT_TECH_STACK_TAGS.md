# Промпт: блок «Технологический стек» + управление тегами с дашборда

Используй как ТЗ для реализации в проекте **portfolio_django** (Django, шаблон `templates/index.html`, модели в `main.models`).

---

## Цели

1. **Визуально модернизировать** секцию `#skills` / «Технологический стек»: ровная, **равномерная** сетка (одинаковая ширина колонок, выровненные карточки категорий, предсказуемые отступы на desktop/tablet/mobile).
2. Перенести контент стека с **жёстко прошитого HTML** на **данные из БД**, чтобы список тегов на главной отражал то, что настроено в **кастомном дашборде** (не `django.contrib.admin`).
3. В дашборде дать UI **управления тегами**: выбор из **dropdown** (или combobox) для **добавления** тега в группу / на главную и явное **удаление** тега (кнопка «×» или пункт в списке).
4. Предзаполнить («подтянуть») **справочник тегов** по направлениям: **Full Stack**, **AI / ML**, **QA / тестирование**, **Python backend**, **Front-end / разработка интерфейсов** — чтобы владелец сайта из дашборда только отмечал, что показывать, без ручного ввода с клавиатуры для типовых технологий.

---

## Модель данных (рекомендуемая)

- **`TechTag`** (справочник):
  - `name` — отображаемое имя (например `Django`, `Playwright`).
  - `slug` — уникальный слаг.
  - `category` — enum/choices: `fullstack`, `ai`, `qa`, `python`, `frontend` (имена согласовать с дизайном: подписи на сайте — человекочитаемые: «Full Stack», «AI / ML» и т.д.).
  - `sort_order` — порядок внутри категории (опционально).
  - `is_active` — можно скрыть из dropdown без удаления.
- **`VisibleTechTag`** или поле на связующей модели «профиль стека»:
  - либо **флаг `show_on_homepage`** у `TechTag` (проще),
  - либо отдельная модель **M2M** «какие теги из справочника выведены на главной» + порядок отображения.
- Миграция **data migration** или management command: создать записи справочника из списка ниже (идемпотентно, `get_or_create` по slug).

Главная страница (`home`): передать в шаблон структуру вида `tech_by_category` — словарь или список категорий с отфильтрованными тегами **только с флагом показа на главной**, отсортированными.

## Стартовый набор тегов (сид в БД)

Сгруппировать примерно так (при необходимости расширить, не дублируя смысл):

| Категория (ключ) | Примеры тегов |
|------------------|---------------|
| **fullstack** | REST API, GraphQL, Microservices, System Design, Monorepo, Django, FastAPI, Flask, Node.js |
| **python** | Python 3, asyncio, Celery, SQLAlchemy, Pydantic, uv, pytest, Poetry, Ruff, Black |
| **frontend** | JavaScript, TypeScript, React, Next.js, Vue, Vite, HTML/CSS, Tailwind CSS, SASS, Webpack |
| **ai** | OpenAI API, LLM, LangChain / LangGraph, RAG, Vector DB (pgvector/Pinecone), NLP, Hugging Face, PyTorch (опционально) |
| **qa** | QA, Manual Testing, Test Cases, pytest, Playwright, Selenium, API Testing, Postman, CI тесты, Test Automation |

Требование: на главной показываются **не все** справочные теги, а только те, что пользователь **включил** в дашборде.

## Дашборд (кастомные HTML-страницы)

- Раздел **«Технологический стек»** или вкладка в существующем дашборде.
- Для **каждой категории**:
  - список уже **добавленных на главную** тегов (чипы) с кнопкой удаления;
  - **dropdown `<select>`** (или Datalist + кнопка «Добавить»): опции — активные теги из справочника **этой категории**, которые **ещё не** выведены на главной;
  - по submit — POST с CSRF, `login_required`.
- Опционально: поле «создать произвольный тег» (редкий кейс) — с валидацией и присвоением категории; либо только справочник без свободного ввода — уточнить в коде по простоте.

## Главная страница — вёрстка «равномерный стек»

- Заменить четыре статических `.tech-category` блока на **цикл** по категориям из контекста (только непустые).
- CSS:
  - контейнер: `display: grid`;
  - на больших экранах — **фиксированное число колонок** (например `repeat(2, 1fr)` или `repeat(4, 1fr)` в зависимости от числа категорий с контентом), чтобы колонки были **одинаковой ширины**;
  - на узких — одна колонка;
  - внутри `.tech-category`: `min-height` или `align-content: start`, одинаковые `padding`, заголовки одной высоты (при необходимости `min-height` для `h3`).
- `.tech-tags`: `display: flex; flex-wrap: wrap; gap: ...` — как сейчас, но убедиться, что визуальная плотность **одинаковая** между карточками.

## Критерии готовности

- На главной секция стека **полностью динамическая**; изменения из дашборда видны без правки `index.html`.
- Dropdown в дашборде позволяет **добавлять** и **удалять** теги с главной по категориям.
- Справочник после миграции содержит релевантный набор по **Full Stack / AI / QA / Python / Front-end**.
- Сетка на десктопе выглядит **ровной** (равные колонки, нет «ломаной» ширины из `auto-fit` при малом числе элементов — при необходимости задать `max-width` контейнера и явное `grid-template-columns`).
